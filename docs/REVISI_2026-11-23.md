## Perubahan logika

1. **Otomatisasi melalui HTML yang sama.** `public/assets/app.js` memakai JavaScript native dan `fetch` same-origin. Respons tetap HTML dari route PHP yang ada; tidak ada framework, API eksternal, atau layanan REST/JSON baru.
2. **Dokumen belum menjadi lamaran.** Unggahan sah disimpan privat dan ID-nya ditahan di sesi. Pengiriman final memeriksa CV, persyaratan, URL, persetujuan, jurusan/semester, duplikasi, dan ketersediaan lowongan. Kesalahan tidak menghilangkan unggahan valid sebelumnya.
3. **Transaksi konsisten.** Hasil seleksi/jadwal/notifikasi dan pemeriksaan/keputusan perusahaan/audit/notifikasi disimpan atomik. Validasi jadwal yang gagal tidak lebih dahulu meloloskan kandidat. Versi peninjauan mencegah keputusan admin menimpa data perusahaan yang berubah.
4. **Hak akses pada backend.** Sesi menentukan role dan pemilik data. Profil mahasiswa read-only bukan hanya input disabled. Dokumen, kandidat, kalender dan perusahaan tetap diperiksa kepemilikannya.
5. **Kompatibilitas data.** Tidak perlu migrasi skema. Kolom dan enum historis tidak dihapus paksa; data lamaran/berkas lama tetap dipertahankan. Detail ada di DATABASE.md.

## Fitur yang tetap dipertahankan

Login lokal tanpa registrasi, tiga role, pencarian dan filter, detail/timeline, PDF privat, tambah/hapus tahap sebelum roadmap terkunci, edit/tutup/hapus lowongan, kuota penerimaan, kalender dan pengingat, notifikasi, chat setelah lolos administrasi, rekap/CSV, konfirmasi pembatalan, serta penghapusan perusahaan dengan riwayat mahasiswa tetap utuh.
